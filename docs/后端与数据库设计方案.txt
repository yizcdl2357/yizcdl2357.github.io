# 后端与数据库设计方案

## 目标

本项目后端采用统一的数据访问层屏蔽数据库差异：

- 本地测试：使用本地文件型数据库，推荐 SQLite，数据库文件如 `data/english-corpus.sqlite`
- 网站部署：使用线上 SQL 数据库，推荐 MySQL
- 业务层不直接依赖具体数据库，只依赖 Repository 接口
- 通过环境变量切换数据库类型，不修改业务代码

## 推荐技术路线

```text
Frontend
  ↓ HTTP / JSON
Backend API
  ↓ Service Layer
Repository Interface
  ↓
Local SQLite Adapter 或 MySQL Adapter
  ↓
SQLite 文件 或 MySQL 数据库
```

环境变量建议：

```env
APP_ENV=local
DB_CLIENT=sqlite
DB_FILE=./data/english-corpus.sqlite

# 部署时使用
DB_CLIENT=mysql
DB_HOST=localhost
DB_PORT=3306
DB_NAME=english_corpus
DB_USER=your_user
DB_PASSWORD=your_password
```

## 数据表说明

### users

保存用户账号信息。

```text
id              主键，建议 UUID
username        唯一用户名
password_hash   密码哈希，不保存明文密码
created_at      注册时间
```

### paragraphs

保存所有语段。

```text
id          主键，建议 UUID
content     语段正文
author_id   上传者，对应 users.id
theme       作文主题
created_at  创建时间
updated_at  更新时间
```

### tags

保存允许选择的固定标签枚举。

```text
开头
结尾
过渡
应用文
读后续写
议论
名言
动作
心理活动
高级表达
```

### paragraph_tags

语段与标签的多对多关联表。

### collections

保存用户收藏关系。应限制同一用户不能重复收藏同一语段。

```text
unique(user_id, paragraph_id)
```

```mermaid
sequenceDiagram

    participant ParagraphController as ParagraphController

    participant ParagraphService as ParagraphService
    participant ThemeService as ThemeService
    participant ParagraphRepository as ParagraphRepository
    participant TagRepository as TagRepository
    participant DB as 数据库

    User->>Frontend: 填写内容、主题、标签并提交
    Frontend->>ParagraphController: POST /api/paragraphs
    ParagraphController->>AuthService: getCurrentUser(sessionId)
    AuthService-->>ParagraphController: 返回当前用户
    ParagraphController->>ParagraphService: createParagraph(userId, content, theme, tags)
    ParagraphService->>ThemeService: detectTheme(content)
    ThemeService-->>ParagraphService: 返回推荐主题或空
    ParagraphService->>TagRepository: validateTags(tags)
    TagRepository->>DB: 查询标签是否存在
    DB-->>TagRepository: 返回标签结果
    ParagraphService->>ParagraphRepository: create(paragraph)
    ParagraphRepository->>DB: 写入 paragraphs 和 paragraph_tags
    DB-->>ParagraphRepository: 返回保存结果
    ParagraphRepository-->>ParagraphService: 返回新语段
    ParagraphService-->>ParagraphController: 返回上传结果
    ParagraphController-->>Frontend: 返回语段ID
    Frontend-->>User: 跳转至语段展示界面
```

## 本地与部署数据库建议

本地测试推荐 SQLite，因为它就是一个本地文件，便于提交 schema、备份和重置；部署时使用 MySQL，连接信息放入环境变量，不提交真实密码。

后端启动时根据 `DB_CLIENT` 决定使用 SQLite 还是 MySQL。两者使用相同表结构和 Repository 接口，避免业务代码分叉。

## 注意事项

- `.env` 不应提交到 GitHub
- 应提交 `.env.example`
- 应提交数据库迁移脚本，如 `database/migrations`
- 本地 SQLite 文件可不提交，只提交建表脚本和种子数据
- 密码只保存哈希值，禁止保存明文密码
- 删除语段时应同步删除 `paragraph_tags` 和 `collections` 中的关联记录
- 标签表只保留允许枚举中的 10 个标签
